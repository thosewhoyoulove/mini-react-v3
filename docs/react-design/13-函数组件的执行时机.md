## 13.1 组件函数只负责产生 children

```js
function Counter() {
  const [count] = useState(0);
  return createElement('p', null, 'count: ' + count);
}
```

处理 Counter Fiber 时，`beginWork` 进入 `updateFunctionComponent`，再由 `renderWithHooks` 调用 `Counter(props)`。输出是一份 `<p>` 描述，不是 DOM。

函数组件 Fiber 的 `stateNode` 通常是 `null`。跨调用保留的数据不在局部变量里，而在 Fiber 上：

```text
fiber.memoizedState → Hook0 → Hook1 → ...
```

同一个 Counter 函数出现在两个位置时，会对应两个 Fiber、两条 Hook 链，因此状态互不共享。

## 13.2 `renderWithHooks` 怎样建立执行上下文

调用组件前，`renderWithHooks` 会：

1. 把 `currentlyRenderingFiber` 指向本轮 WIP；
2. 清空 WIP 的 Hook 链、Effect 队列和 context 依赖；
3. 根据 current 是否已有 Hook 链选择 mount 或 update Dispatcher；
4. 在 `try` 中执行 `Component(props, ref)`；
5. 在 `finally` 中清空 Dispatcher 和所有游标。

组件之外调用 `useState(0)` 时，Dispatcher 是 `null`，会抛：

```text
Invalid hook call. Hooks can only be called inside function components.
```

ForwardRef 和 Memo 最终也会进入 `renderWithHooks`。区别只是实际执行哪个 render 函数，以及是否在此前比较 props。

组件不一定每次更新都执行。props、ref、context 都没变，并且自己和子树没有本轮 lane 时，`beginWork` 会 bailout，复用 current 的 child 结果。这和「组件执行了，但 Effect deps 没变」是两件不同的事。

## 13.3 顺序为什么是 Hook 的身份

Hook 没有显式 key。第几次调用就是第几格：

```text
Hook0  第一次 useState
Hook1  useRef
Hook2  useEffect
```

更新时，current 链和 WIP 链按相同顺序逐格对齐。条件调用会让后续格子错位：

```js
if (visible) {
  useState(0);
}
useEffect(sync, []);
```

`visible` 改变后，第二次调用不再对应上一轮同一格。当前实现若多调用 Hook，会抛 `Rendered more hooks than during the previous render`；少调用的开发期检查没有官方 React 那么完整。

因此规则不是「Hook 函数比较特殊」，而是当前数据结构用稳定调用顺序识别状态。下一章展开这条链如何 mount 和 update。

## 面试复习

### 一句话结论

函数组件在 Render 的 `beginWork` 阶段执行，只返回 children；跨渲染数据保存在对应 Fiber 的 Hook 链上。

### 常见追问

**Commit 会再次执行组件吗？**

不会。Commit 消费 flags、修改宿主并执行 Effect。

**bailout 与 Effect deps 不变有什么区别？**

bailout 时整个组件函数不执行；deps 不变则组件已经执行，只是本轮不登记 Effect 工作。
