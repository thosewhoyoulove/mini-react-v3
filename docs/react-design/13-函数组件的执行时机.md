# 第 13 章：函数组件什么时候执行

[← 返回总目录](../../React设计与实现.md) · [上一章](./12-Commit三阶段.md) · [下一章 →](./14-Hook链表与Dispatcher.md)

---

写下 `createElement(App)` 时，我们只是把 `App` 这个函数放进 React Element，并没有执行它。Commit 阶段忙着修改宿主环境，也不会回来调用组件。真正的调用发生在哪里？沿着一次 Counter 的 render 往下看，就能把组件函数、Fiber 和 Hook 串起来。

## 13.1 组件函数只负责产生 children

```js
function Counter() {
  const [count] = useState(0);
  return createElement('p', null, 'count: ' + count);
}
```

Render 处理 Counter Fiber 时，`beginWork` 会进入 `updateFunctionComponent`，后者再把组件交给 `renderWithHooks`。直到这里，`Counter(props)` 才真正执行。它返回的是下一层 children，也就是一份 `<p>` 的元素描述，DOM 还没有产生。

函数执行结束后，`count` 这个局部变量随调用一起结束。需要跨 render 保留的数据由 Counter 对应的 Fiber 记住：

```text
fiber.memoizedState → Hook0 → Hook1 → ...
```

函数组件 Fiber 的 `stateNode` 通常为 `null`，Hook 链则挂在 `memoizedState` 上。同一个 `Counter` 即使在页面里出现两次，也会得到两个 Fiber；每个 Fiber 各自保存一条 Hook 链，状态自然彼此独立。

## 13.2 `renderWithHooks` 怎样建立执行上下文

`renderWithHooks` 不会一上来就调用组件。它先让 `currentlyRenderingFiber` 指向本轮正在构建的 WIP Fiber，清空 WIP 上一次留下的 Hook 链、Effect 队列和 context 依赖，再根据 current 上是否已有 Hook 链，装入 mount 或 update Dispatcher。

准备好这些临时状态之后，它才在 `try` 中执行 `Component(props, ref)`。无论组件正常返回还是中途抛错，`finally` 都会清空 Dispatcher 和各个游标。这样，上一轮组件的 Hook 上下文不会泄漏到下一次调用。

也正因为这套上下文只在组件执行期间存在，在组件外调用 `useState(0)` 时，Dispatcher 是 `null`，程序会抛出：

```text
Invalid hook call. Hooks can only be called inside function components.
```

ForwardRef 和 Memo 最后也会走进 `renderWithHooks`。前者传入自己的 render 函数，后者可能先比较 props，但 Hook 执行所依赖的上下文并没有换一套。

还有一种情况，组件函数根本不会被调用：props、ref、context 都没有变化，组件自身和子树也没有本轮 lane 时，`beginWork` 可以 bailout，直接复用 current 的 child。这和 Effect deps 不变不同：后者已经执行了组件，只是没有登记本轮 Effect 工作；bailout 则连组件函数都跳过了。

## 13.3 顺序为什么是 Hook 的身份

Hook 没有显式 key，也不认识局部变量名。React 只看它在组件执行过程中排在第几次调用：

```text
Hook0  第一次 useState
Hook1  useRef
Hook2  useEffect
```

更新时，current 链和 WIP 链从头开始逐格对齐。于是下面的条件分支会制造错位：

```js
if (visible) {
  useState(0);
}
useEffect(sync, []);
```

假如上一轮 `visible` 为 `true`，`useEffect` 对应第二格；下一轮它变成 `false`，`useEffect` 就成了第一次 Hook 调用，读到的却是旧链第一格。链表没有名字可用来重新寻找正确位置。

本实现会在本轮调用数量多于上一轮时抛出 `Rendered more hooks than during the previous render`，对 Hook 变少的开发期检查则没有官方 React 那么完整。报错只是保护手段，稳定的调用顺序才是两轮状态能够对齐的基础。

## 本章回顾

- 函数组件在 Render 的 `beginWork` 路径中由 `renderWithHooks` 调用，返回 children；Commit 不会再次执行它。
- 局部变量属于一次函数调用，跨 render 的 Hook 数据保存在对应 Fiber 的 `memoizedState` 链上。
- bailout 会跳过整个组件函数；Effect deps 不变时，组件已经执行，只是本轮不登记 Effect 工作。
- Hook 依靠调用位置对齐状态，所以每轮执行都要保持相同顺序。

源码可从 `packages/react-reconciler/src/beginWork.ts` 的函数组件与 bailout 分支，以及 `packages/react-reconciler/src/hooks.ts` 的 `renderWithHooks` 开始阅读。
