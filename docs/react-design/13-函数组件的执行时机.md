## 13.1 函数组件没有实例

`createElement(App, null)` 的 `type` 是函数 `App` 本身。对应 Fiber 的 `tag` 是 `FunctionComponent`，`stateNode` 一般是 `null`——没有 class 那种挂载在实例上的 `this.state`。

每次 Render 走到这个节点，框架就再调一次 `App(props)`。返回值（Element / 数组 / 文本）当作 children 去 Diff。状态不活在函数的局部变量里（那会随调用结束而消失），而活在 Fiber 的 Hook 链表上：`fiber.memoizedState → Hook0 → Hook1 → …`。

可以记成：

```text
函数组件 = 一次调用 + 挂在 Fiber 上的 Hook 链表
调用产生描述；链表跨调用记住 state / effect
```

没有实例，也就没有 `componentDidMount` 那种「实例方法」。副作用改挂到 Hook 上，由 Commit 按阶段调用。

## 13.2 在 `beginWork` 里调函数

调用点只有一处：`updateFunctionComponent` → `renderWithHooks`。

```ts
ReactCurrentDispatcher.current =
  current == null || current.memoizedState == null
    ? HooksDispatcherOnMount
    : HooksDispatcherOnUpdate;

const children = Component(props);
```

调用前要先把「当前是谁」挂好：

1. `currentlyRenderingFiber = workInProgress`——第一个 Hook 写成它的 `memoizedState`。
2. 清空 wip 上旧的 Hook 链表和两个游标，本轮从头接。
3. 按有没有 current 链表切换 dispatcher。
4. **这时才** `Component(props)`。里面的 `useState` 读到的就是刚设的 dispatcher。
5. 跑完立刻把模块级指针清掉，避免漏到下一个组件。

所以 Hook 只能出现在函数组件体里、且必须发生在这次 `beginWork` 的调用栈中。在事件处理函数、`setTimeout`、模块顶层调用 `useState`，`ReactCurrentDispatcher.current` 是 `null`，会抛：

```text
Invalid hook call. Hooks can only be called inside function components.
```

上下文挂在当前 Fiber 上，不是挂在「名为 App 的那个函数」上。同一个函数用在两棵子树，是两个 Fiber、两条 Hook 链表。

## 13.3 为什么 Hook 不能写在条件分支里

Hook **没有名字**。身份就是「本组件第几次调用 `useXxx`」：

```text
fiber.memoizedState → Hook0（第一次 useState）
                   → Hook1（第一次 useEffect）
                   → Hook2（第二次 useState）
```

更新时 `updateWorkInProgressHook` 严格按这个顺序，从 current 链表一格一格对齐。写进 `if` 会让两次渲染的「第 N 次调用」对不上：

```ts
if (flag) {
  useState(0); // 有时是第 1 格，有时整格消失
}
useEffect(...); // 本该永远是第 2 格，flag 为真时变成第 3 格
```

current 链表走完还在调 Hook，就会抛 `Rendered more hooks than during the previous render`。少调一次则后面对齐的是别人的 queue，state 会串台。

规则可以收成一句：**顺序即身份。** 下一章看链表怎么接、两套 dispatcher 怎么切换。

## 面试复习

### 一句话结论

函数组件是在 Render 的 `beginWork` 向下阶段被当作普通函数执行的；函数只生成 children，跨渲染状态由对应 Fiber 的 Hook 链表保存。

### 面试回答（为什么→机制→仓库落点→官方差异）

为什么：函数调用结束后局部变量会消失，又没有 class 实例承载状态。机制：`updateFunctionComponent` 先进入 `renderWithHooks`，设置正在渲染的 Fiber、Hook 游标和 mount/update Dispatcher，再调用 `Component(props)`，返回值交给子节点 Diff。仓库落点：调用点在 `beginWork.ts`，上下文准备与清理在 `hooks.ts`。官方差异：核心模型一致，但官方还有 bailout、render phase update、严格模式开发检查等路径，本仓库只保留一次执行与顺序对齐的主线。

### 常见追问

**Q：函数组件何时执行，Commit 时还会再执行吗？**
A：在 Render 的 `beginWork` 阶段执行；Commit 只消费 flags、操作 DOM 和执行 effect，不重新调用组件函数。

**Q：同一个组件函数渲染两次会共享 state 吗？**
A：不会。状态属于 Fiber 上的 Hook 链表；两个位置对应两个 Fiber，也就是两份状态。

**Q：为什么事件回调里不能直接调用 Hook？**
A：组件执行结束后 Dispatcher 已被清空，事件回调不在 `renderWithHooks` 建立的渲染上下文中。

### 容易说错

- 不要说「组件函数返回 DOM」；它返回 Element / 数组 / 文本等子树描述。
- 不要说 state 存在函数或闭包里；闭包只捕获某次渲染的值，持久状态在 Fiber Hook 链表。
- 不要把 effect 的 create 说成函数组件执行时运行；这里只登记 Effect，执行在 Commit。
