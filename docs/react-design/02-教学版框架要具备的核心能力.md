应用只描述下一帧，不等于框架可以简单地清空容器再重建。小页面上，这种实现似乎也能工作；树一大、更新做到一半需要暂停，或者渲染目标不再是浏览器，问题就会接连出现。一个适合继续扩展的教学框架，至少要把工作进度、可见页面和宿主操作分开。

## 2.1 整页重建会堵住主线程

先看最省事的声明式运行时。下面的伪代码省略了属性、事件和错误处理，不是项目实现，也不能直接替代 React：

```js
function render(element, container) {
  container.innerHTML = '';
  mount(element, container);
}

function mount(element, parent) {
  if (typeof element.type === 'function') {
    mount(element.type(element.props), parent);
    return;
  }
  const node = document.createElement(element.type);
  parent.appendChild(node);
  const children = element.props.children;
  const list = Array.isArray(children) ? children : [children];
  for (const child of list) {
    if (child == null || child === false) continue;
    if (typeof child === 'string' || typeof child === 'number') {
      node.appendChild(document.createTextNode(String(child)));
    } else {
      mount(child, node); // 子树不返回，这一层就出不去
    }
  }
}
```

`render` 先清空旧内容，再递归创建整棵 DOM 子树。树很小时看不出问题；节点一多，主线程必须等这次递归返回后才能继续处理输入和绘制。

想把工作拆成几段，框架需要明确知道「下一个处理谁」。普通递归把进度藏在 JavaScript 调用栈里，`mount` 不等子树完成就无法回到父层，也没有一个可保存的兄弟节点断点。

Fiber 把树改写成由 `child`、`sibling` 和 `return` 指针连接的工作单元。工作循环每处理一个 Fiber，都可以把下一个节点留在 `workInProgress` 中。本项目的 `root.render` 使用 `SyncLane`，会在微任务里一次跑完；普通 `setState` 使用 `DefaultLane`，可由 Scheduler 分片执行。两条路径是否让出主线程不同，但都依赖同一套可逐节点推进的结构。

## 2.2 边算边改 DOM 时不能把半成品露在屏幕上

把遍历拆开后，又会遇到一个问题：如果每完成一个节点就立刻修改已显示的 DOM，一次暂停可能让用户看见两帧之间的半成品。列表前半段已经倒序，后半段仍是旧顺序，或者暂时缺少节点。

计算中的结构不能直接替代已经提交的结果。本项目为同一逻辑位置保留 current 和 work-in-progress 两个 Fiber：

```text
current         已经提交、屏幕上对应的那棵
workInProgress  这一轮正在算的那棵
```

Render 阶段在 `workInProgress` 上比较节点并记录 flags。`completeWork` 也可以先创建尚未挂进文档的 DOM，但只有整棵树完成后，Commit 才修改页面，并把根的 `current` 切换到新树。时间片用完时，暂停的是内存中的遍历；屏幕继续显示上一次已经提交的内容。

这不是复制两份完整 DOM。双缓冲主要发生在 Fiber 层，宿主节点能复用时仍会复用。框架为此要维护两棵 Fiber 的对应关系，却获得了一个关键能力：未完成的计算可以暂停或放弃，而不会直接露给用户。

## 2.3 决定怎么改的代码不该认识 document

前面的伪代码还把 `document.createElement` 写进了遍历过程。这样一来，「哪些子节点可以复用」和「浏览器怎样创建节点」混在一起。换成其他渲染目标时，连比较树的算法也要跟着改。

项目把宿主操作收进 `HostConfig`，再由 `react-dom` 完成组装：

```ts
// packages/react-dom/src/client.ts
export function createRoot(container: Element) {
  ensureRootClickDelegation(container);
  const root = createContainer(container, hostConfig);
  return {
    render(element: ReactElement) {
      updateContainer(element, root);
    },
  };
}
```

`createContainer` 把容器和 `hostConfig` 保存在 `FiberRoot` 上。调和器负责计算要创建、更新或删除哪些节点；到了需要操作宿主的时候，再调用函数表中的 `createInstance`、`appendChild`、`commitUpdate` 等方法。浏览器相关代码留在 `react-dom`，`react-reconciler` 不直接访问 `document`。

三部分连起来，更新路径有了清楚的分工：

```text
Fiber 工作单元             保存遍历进度，允许逐节点推进
current / workInProgress   隔开已提交结果和本轮计算
HostConfig                 把调和结果翻译成具体宿主操作
```

## 本章回顾

- Fiber 把递归树遍历变成可逐个处理的工作单元，`workInProgress` 可以保存下一处断点。
- current 保留已提交结果，work-in-progress 承接本轮计算；Render 可以暂停，Commit 再集中修改可见页面。
- `HostConfig` 隔开调和算法与 DOM API，让同一套比较过程不必依赖 `document`。
