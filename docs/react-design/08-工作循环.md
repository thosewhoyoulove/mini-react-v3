## 8.1 一个 Fiber 就是一个工作单元

`workInProgress` 指向下一格待处理 Fiber。`performUnitOfWork` 的主路径是：

```ts
const next = beginWork(
  current,
  unitOfWork,
  workInProgressRootRenderLanes,
);
unitOfWork.memoizedProps = unitOfWork.pendingProps;
unitOfWork.lanes = removeLanes(
  unitOfWork.lanes,
  workInProgressRootRenderLanes,
);

if (next == null) {
  completeUnitOfWork(unitOfWork);
} else {
  workInProgress = next;
}
```

输入是 current、这一轮的 WIP Fiber 和本轮 `renderLanes`。输出有两种：`beginWork` 返回 child，循环继续向下；返回 `null`，说明这条分支没有更深的工作，转入向上完成。

`renderLanes` 不能省略。`beginWork` 会用它判断当前节点或子树是否还有本轮工作，从而决定执行组件，还是 bailout。处理成功后，本轮 lane 从节点的 `lanes` 中移除，`pendingProps` 也成为本轮使用过的 `memoizedProps`。

真实函数外面还有 `try/catch`。组件若抛出 thenable，`unwindWork` 向上找 Suspense；若抛普通错误，则找带 `isErrorBoundary` 的函数组件。找到后打 `DidCapture`，把 `workInProgress` 指回边界，让下一次 `beginWork` 改渲染 fallback。主线先记住：正常路径一次处理一格，异常路径也要把「下一格」恢复到某个边界。

## 8.2 `child`、`sibling`、`return` 怎样走完整棵树

对第 6 章的小树，实际顺序是：

```text
begin HostRoot → div → h1 → "Mini React"
complete "Mini React" → complete h1
begin p → "count: 0"
complete "count: 0" → complete p → complete div → complete HostRoot
```

到叶子后，`completeUnitOfWork` 反复执行三步：

1. `completeWork` 完成当前节点；
2. 有 `sibling`，下一格就是兄弟，停止回溯；
3. 没有兄弟，沿 `return` 回到父节点，继续 complete。

父节点一定晚于孩子完成。因此 Text 可以先创建 `stateNode`，`h1` 随后把 Text 挂进自己的离屏实例；父节点也能在孩子已经汇总完之后计算 `subtreeFlags`。

一直回到 HostRoot 后，`workInProgress` 变成 `null`，表示 Render 完成。`finishRoot` 把 `root.current.alternate` 记为 `finishedWork`，移除本轮已经处理的 lanes，再进入 `commitRoot`。如果根上还留着其他 lane，Commit 后会继续调度下一轮。

## 8.3 同步、切片与重启

两套循环都调用同一个 `performUnitOfWork`：

```ts
function workLoopSync(): void {
  while (workInProgress != null) {
    performUnitOfWork(workInProgress);
  }
}

function workLoopConcurrent(): void {
  while (workInProgress != null && !unstable_shouldYield()) {
    performUnitOfWork(workInProgress);
  }
}
```

| 路径 | 当前仓库中的入口 | 怎样投递 | 是否让出 |
| --- | --- | --- | --- |
| Sync | `root.render` 的 `SyncLane` | 微任务 | 不检查 `shouldYield`，一次走完 |
| Concurrent | 普通 `setState` 的 `DefaultLane`、`startTransition` 的 `TransitionLane` | Scheduler 宏任务 | 每个 Fiber 之间检查时间片 |

微任务只表示 Sync 何时开始，不表示它会切片。Concurrent 也不是多线程：JavaScript 仍在主线程串行执行，只是在工作单元之间合作式让出。

时间片用完时，`workInProgress` 仍指向下一格，下一次 Scheduler 回调可以继续。第一拍或必须重启时，`prepareFreshStack` 才会从 `root.current` 准备新的 WIP 根；普通续跑不会重复调用它。

渲染过程中若来了同档或更高优更新，已经 begin 过的节点可能看不到新 Hook 队列。当前实现会设置 `rootNeedsRestart`，丢掉半成品，从 current 根重新准备 WIP。更低优更新留在 `pendingLanes`，等本轮 Commit 后再处理。具体的 Lane 选择留到第 18 章。

## 面试复习

### 一句话结论

工作循环把一个 Fiber 定义为一个工作单元，用 `workInProgress` 保存下一步；向下 `beginWork`，到叶子后向上 `completeWork`。

### 常见追问

**时间片用完后怎样恢复？**

循环退出时不清空 `workInProgress`。下一次 Scheduler 回调继续这一格；只有结果失效时才从 current 根重启。

**Concurrent Rendering 是多线程吗？**

不是。本仓库在主线程上分多个宏任务运行，并只在 Fiber 工作单元之间检查是否让出。

**为什么父节点必须最后 complete？**

父宿主实例要收集已经创建好的子实例，父 Fiber 也要汇总孩子的 flags 和 lanes。
